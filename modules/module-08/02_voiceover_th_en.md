- **Display Script (TH):**

## LESSON M8-L3: Deep Root Cause Analysis (`5 Why`, `Is/Is-Not`, `FTA` & `Poka-Yoke`)

### AUD-M8L3-S01 (40 sec) — Direct vs Root vs Systemic Cause
- **Display Script (TH):**  
  ทำไมโรงงานแก้ปัญหาเดิมซ้ำแล้วซ้ำอีก? เพราะหยุดแค่ **Direct Cause เหนือน้ำ** เช่น *"แคลมป์หลวมก็ขันใหม่"* [PAUSE-1] [ANIM: iceberg_causes] การสืบที่ดีต้องดำลงใต้น้ำไปให้ถึง **Technical Root Cause** เช่น ซีลรั่วและไม่มีสวิตช์ตัดเครื่อง และลึกลงไปถึง **Systemic Cause** เช่น ขาดรอบ PM เปลี่ยนซีลและ Control Plan ไม่แยก Fixture
- **TTS Clean Script (TH):**  
  ทำไมโรงงานแก้ปัญหาเดิมซ้ำแล้วซ้ำอีก เพราะหยุดแค่ ไดเรกต์ คอส เหนือน้ำ เช่น แคลมป์หลวมก็ขันใหม่, การสืบที่ดีต้องดำลงใต้น้ำไปให้ถึง เทคนิคอล รูท คอส เช่น ซีลรั่วและไม่มีสวิตช์ตัดเครื่อง และลึกลงไปถึง ซิสเทมิก คอส เช่น ขาดรอบ พีเอ็ม เปลี่ยนซีลและ คอนโทรล แพลน ไม่แยก ฟิกซ์เจอร์
- **EN Reference:**  
  Recurring defects happen when teams fix surface symptoms alone. Dig beneath the waterline to expose both technical root causes and systemic control plan gaps.

### AUD-M8L3-S02 (45 sec) — 3-Legged 5 Why & Therefore Test
- **Display Script (TH):**  
  การเขียน **5 Why** ให้มืออาชีพ ห้ามจบด้วยคำว่า *"พนักงานสะเพร่า"* ! [PAUSE-1] [ANIM: three_leg_five_why] ต้องเดินให้ครบ **3 ขา** คือ **ทำไมถึงเกิด (Occurrence)**, **ทำไมถึงตรวจไม่เจอ (Detection)**, และ **ทำไมระบบถึงปล่อยผ่าน (Systemic)** [PAUSE-1] เสร็จแล้วต้องทดสอบอ่านย้อนจากล่างขึ้นบนด้วยคำว่า **"ดังนั้น... จึงเกิด..." (Therefore Test)** ว่าตรรกะเชื่อมกันสนิทไหม
- **TTS Clean Script (TH):**  
  การเขียน ไฟว์ วาย ให้มืออาชีพ ห้ามจบด้วยคำว่า พนักงานสะเพร่า, ต้องเดินให้ครบ 3 ขา คือ ทำไมถึงเกิด ทำไมถึงตรวจไม่เจอ และ ทำไมระบบถึงปล่อยผ่าน, เสร็จแล้วต้องทดสอบอ่านย้อนจากล่างขึ้นบนด้วยคำว่า ดังนั้น จึงเกิด หรือ แดร์ฟอร์ เทสต์ ว่าตรรกะเชื่อมกันสนิทไหม
- **EN Reference:**  
  Never stop a 5 Why at operator blame. Trace three legs—occurrence, detection, and systemic—and validate your chain upward with the Therefore Test.

### AUD-M8L3-S03 (45 sec) — Is / Is-Not & Fault Tree Analysis (`FTA`)
- **Display Script (TH):**  
  สำหรับเคสที่ซับซ้อน ให้ใช้ **Is / Is-Not Matrix** ตีกรอบสิ่งที่ **"ใช่"** เทียบกับ **"ไม่ใช่"** [ANIM: is_not_fta] เช่น เกิดเฉพาะ Fixture B แต่ไม่เกิดบน Fixture A ทั้งที่ใช้วัตถุดิบและคนเดียวกัน ช่วยตัดผู้บริสุทธิ์ออกทันที! [PAUSE-1] แล้วใช้ **Fault Tree (`FTA`)** แยกเงื่อนไขร่วม **`AND Gate`** ออกจากเหตุเดี่ยว **`OR Gate`** เพื่อปิดจุดอ่อนให้ครบ
- **TTS Clean Script (TH):**  
  สำหรับเคสที่ซับซ้อน ให้ใช้ อิส อิส นอต เมทริกซ์ ตีกรอบสิ่งที่ ใช่ เทียบกับ ไม่ใช่ เช่น เกิดเฉพาะ ฟิกซ์เจอร์ บี แต่ไม่เกิดบน ฟิกซ์เจอร์ เอ ทั้งที่ใช้วัตถุดิบและคนเดียวกัน ช่วยตัดผู้บริสุทธิ์ออกทันที, แล้วใช้ ฟอลต์ ทรี เอฟทีเอ แยกเงื่อนไขร่วม แอนด์ เกต ออกจากเหตุเดี่ยว ออร์ เกต เพื่อปิดจุดอ่อนให้ครบ
- **EN Reference:**  
  Use Is/Is-Not matrices to eliminate innocent factors, and build Fault Trees separating AND gates from OR gates so every contributing chain is addressed.

- **Display Script (TH):**
